# Platform v2 packet 1 — implementation and integration proposal

15 November 2026. Additive to the frozen parallel contract; that document and v1 remain unchanged. This packet elaborates fields that the planning contract left abstract. B must review these elaborations and the engine request/response types before enabling its v2 client in production. No claim of connected v2 UI/real model acceptance.

The exact generated request schemas are in `tests/contracts/platform/openapi-v2.json`. Actual synthetic HTTP responses, including replay, conflict, partial balance, queued export and anonymous denial, are in `tests/contracts/platform/http_examples.json`. Canonical QA input provenance and the separately authored dated 1B are in `canonical_inputs.json`. These fixtures are not provider outputs.

All ordinary routes use the existing verified account cookie. Browser writes retain Origin, `X-CSRF-Token`, `X-Bindr-Account`, and `Idempotency-Key`; case changes require an integer `expected_version`. No owner/storage path is accepted from the client. Dates retain timezone, precision and provenance. Capture drafts contain exact text/metadata/evidence IDs; they are distinct from existing complaint wording drafts. Capture before first successful autosave and actual browser remount recovery belong to B. Unuploaded files cannot survive process loss without reattachment.

Operation replay: same account + operation scope + key + canonical request returns the original successful result, including original version. Changed data returns 409 `IDEMPOTENCY_CONFLICT`; a stale new operation returns 409 `VERSION_CONFLICT`. Failed transactions roll back their reservation and all facts; failed extraction diagnostics are separate safe job records. Keep a key on uncertain responses; do not create a new operation to hide ambiguity. Private downloads always go through authorization; no public/signed object URLs.

Every row above is relative to `/api/v2` after the first full path. Connector-specific paths and approval gates are elaborated in `CONNECTORS_V1_PROPOSAL.md`.

`Terms` uses kind refund/replacement/repair/delivery/service/other, description, nullable nonnegative integer `amount_minor` plus nullable ISO currency, and nullable offset-aware `due_at`. Supported currencies are explicitly INR/USD/EUR/GBP/JPY/AUD/CAD/SGD. No float sums or mixed-currency total. Sources use evidence_id, verbatim quote, optional page/message_id and audio offsets; a missing email/audio processor returns a typed unavailable response, never an invented transcript. Original audio/EML/MSG can be retained privately; their connected processing remains an intelligence integration gate.

Communication is `{date:null|'YYYY-MM-DD',time:null|'HH:mm:ss',timezone,precision:'unknown'|'date'|'timestamp',provenance,original_wording}`. Invalid calendar dates reject. Future communication dates remain unchanged and require visible review; capture responses contain the warning. Unknown import dates are not invented as message dates. Date-only deadline proposals stay dates, without fabricated midnight. Explicit clocks preserve local time; ambiguous/nonexistent DST instants require manual offset selection. Custom holiday sets are user-supplied, not an officially verified regional calendar.

Ledger policy: partial is a genuine incomplete receipt; the final balance requires explicit `full`. Pending/company_claim cannot record receipt amounts or close obligations. Nonfinancial partial progress uses a note, no fake money. Corrections append a void reference to an outcome, without erasing it. Revisions retain predecessor/source rows and inherit prior receipt history; currency changes or reducing promised money below receipts reject. Case reopening preserves all receipts and does not silently undo fulfilled obligations; correct a receipt or explicitly add/revise an obligation where needed. Archive hides from the default workspace and cancels reminders.

The v2 engine request is data-only `{schema_version:2,case_id,evidence:[{evidence_id,text,pages,communication}],existing_obligations,context:{operation_id,timeout_seconds,timezone}}`. The output is the frozen proposal envelope; precise Candidate/Temporal/Relation/Condition types appear in the generated schema. A calls `extract_proposals_v2(request)` and the proposed `answer_case_v2(request)`; missing methods fail 503, without changing the v1 adapter or enabling mocks. Test engines are dependency overrides only. Raw provider errors are redacted; failures record stage, elapsed time and a job/request ID without source bodies or secrets. Engine calls are bounded, never auto-retried, and late pure results cannot persist.

Remaining joint gates: B's reviewed compatibility with these elaborations; real v2 engine/client; original blocked semantic tests through save/reload; actual browser security/remount/two-tab checks; configured-provider acceptance. A fixture passing is not a substitute.

Final additions: case events expose causal `sequence` and `case_version`; old ties are not fabricated. Exports accept optional `obligation_ids` only with `include_history:false` to prevent unrelated facts leaking through history/totals. All-selected remains the default. `/verification-info` is public generic instruction data only. Selected originals may themselves contain additional text; they are not silently redacted. QR encoding is optional via a configured generic URL. PDF/data/bundle generation and exact source files are separate artifacts.
